## Что изменено

- Уникальные title, description, один видимый H1; на главной в H1 названа имплантация зубов. Существующие адреса услуг сохранены.
- Абсолютные canonical, Open Graph и связанный граф JSON-LD: Dentist, WebSite, WebPage/MedicalWebPage, Service, BreadcrumbList, BlogPosting, ItemList. Данные клиники согласованы с видимыми контактами.
- Короткие ответы, FAQ, оглавления, списки, понятный состав стоимости. FAQ в JSON-LD совпадают с доступными в HTML текстами; расширенные сниппеты не обещаются.
- В статьях указаны редакция, дата, первичные медицинские источники и информационное назначение. Авторство и рецензирование врачом не выдуманы. Цены импортируются из `content/pricing.mjs`.
- Шесть статей доступны в исходном HTML без выполнения JavaScript. Отзывы также представлены текстом наряду с внешним виджетом.
- XML-карта содержит 17 публичных страниц, включая каталог врачей. Сервер выдаёт правильные MIME-типы XML/TXT, редиректит адреса разделов без завершающего `/`. Закрытые файлы не включены в сборку и sitemap.
- Нет искусственного AggregateRating из выбранных отзывов, несуществующих врачей, координат и обещаний результата.

GEO здесь означает понятный фактический контент, доступные источники, согласованные сущности и перелинковку. Специальный файл для ИИ или отдельная «AI schema» не требуются для AI-функций Google; включение в ответы ИИ не гарантируется. Основание: [Google Search Central — AI features](https://developers.google.com/search/docs/appearance/ai-features), [Article structured data](https://developers.google.com/search/docs/appearance/structured-data/article), [Schema.org Dentist](https://schema.org/Dentist).

## Генерация и режимы индексации

Контент услуг — `content/services.mjs`, статей — `content/blog.mjs`, ответы главной — `content/answers.mjs`, основные данные и домен — `content/site.mjs`. Публичный список страниц — `scripts/public-pages.mjs`. После редактирования:

```powershell
node scripts/build-pages.mjs
node --test tests/*.test.mjs
```

Обычная сборка и локальные исходные страницы остаются **noindex,nofollow**; robots содержит `Disallow: /`. Canonical уже указывает основной домен. GitHub Pages workflow сохраняет режим предпросмотра.

Для готовой к индексации сборки под подтверждённый домен:

```powershell
node scripts/build-pages.mjs --production
```

Результат — папка `site/`: canonical на основном домене, `index,follow,max-image-preview:large`, robots с разрешением публичного сайта и ссылкой на sitemap. Запуск этой команды создаёт файлы и **не публикует сайт**. Исходные HTML для локального сервера остаются noindex.

Альтернативный основной URL, в том числе подкаталог, передаётся явно в окружении процесса сборки:

```powershell
$env:SITE_URL='https://имплантация-челны.рф/'
node scripts/build-pages.mjs --production
Remove-Item Env:SITE_URL
```

`SITE_INDEXABLE=true` также доступен для CI вместе с явным `SITE_URL`. Сборщик не читает `.env` с серверными секретами: параметры передаются через окружение или `--production`. Производственная сборка не публикует backend, панель заявок, research и персональные данные. Старые сгенерированные HTML статей/услуг удаляются из `site/` точечно по разрешённым каталогам при смене slug.

`robots.txt` действует только по адресу `/robots.txt` корня домена. Для GitHub Pages в подкаталоге файл не управляет всем origin; режим noindex обеспечивают метатеги каждой страницы.

## Перед фактическим запуском продвижения

Разместить production-сборку на подтверждённом домене с HTTPS; настроить единственный вариант домена и серверные 301-редиректы при переносе старых адресов. Старый сайт сейчас не изменялся. Проверить согласование медицинских текстов клиникой, документы и действующие контакты. После публикации проверить публичные canonical/robots/sitemap и добавить sitemap в Яндекс Вебмастер и Google Search Console. Доступов к этим кабинетам и хостингу в данном этапе не запрашивалось.

Технические проверки кода не подтверждают индексацию, позиции, цитирование ИИ или медицинскую рецензию. Медицинские источники указаны непосредственно под каждой статьёй; источники технических решений — выше.
