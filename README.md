# PREMIER — лендинг имплантации

## Страницы услуг

Каталог: http://127.0.0.1:4173/services/ . Добавлены одномоментная имплантация, All-on-4, All-on-6, Dentium, Astra Tech и стоматолог-ортопед. Карта семантики, источники и структура ортопедии описаны в `SERVICE-STRUCTURE.md`.

После изменений `content/services.mjs` или общего header/footer запустите `node scripts/generate-services.mjs`. Команда `node scripts/build-pages.mjs` выполняет генерацию автоматически. Для полной проверки: `node --test tests/*.test.mjs`.

Адаптивный лендинг для рекламы имплантации одного или нескольких зубов. Дизайн: молочный фон, графит, персиковые акценты, Manrope и редакционная типографика. Оригинальные логотип и фотографии клиники. Основная версия — мобильная, от 320 px.

## Запуск

Требуется Node.js 22.16+ или 24 LTS. Внешних зависимостей и сборки нет.

```powershell
node server.mjs
```

Открыть http://127.0.0.1:4173. Сервер по умолчанию доступен только на этом компьютере. Остановка — Ctrl+C. Не открывать `index.html` через `file://`: обработчик заявок требует HTTP.

## Проверки

```powershell
node --check server.mjs
node --check app.js
node --test tests/server.test.mjs
```

Интеграционный тест поднимает изолированный сервер на 4174, проверяет выдачу страницы, недоступность служебных файлов и данных, валидацию, проверку Origin, повторную заявку и конфликт идентификатора. Использует вымышленный тестовый номер. Временная папка теста удаляется после проверки.

## Что работает

- Мобильное меню, якоря, звонок и переход на карту.
- FAQ на семантических `details`/`summary`.
- Модальная форма с клавиатурной навигацией, Escape и возвратом фокуса.
- Проверка телефона и согласия на клиенте и сервере.
- Локальное сохранение заявки, защита от повторной отправки, ограничение размера и частоты запросов.
- Защищённая от HTTP-доступа папка `data`, без персональных данных в логах.
- Истёкшая акция удалена с главной.
- Локальные изображения и шрифты. На главной и странице отзывов подключён внешний MyReviews.

## Заявки и режим предпросмотра

Без `LEAD_WEBHOOK_URL` заявки сохраняются в `data/<UUID>.json`. На экране подтверждения явно сказано, что это локальная версия и данные не переданы клинике. Для реальной записи предоставлен телефон. Не вводите реальные данные пациентов при тестировании.

Успех локального теста **не подтверждает** доставку администратору клиники.

Чтобы подключить CRM, скопируйте `.env.example` в `.env`. Заполните `LEAD_WEBHOOK_URL` и при необходимости `LEAD_WEBHOOK_TOKEN`. Переданные поля: `id`, `name`, `phone`, `consent`, `createdAt`, `source`. Отправка: HTTPS POST JSON, `Idempotency-Key` равен `id`. CRM должна поддерживать идемпотентность по этому ключу. Успешный HTTP 2xx считается подтверждением приёма. Таймаут — 9 секунд. При ошибке заявка сохраняется со статусом `pending`, пользователь получает сообщение об ошибке и может повторить отправку. Автоматическая фоновая доставка не реализована; перед запуском нужно согласовать обработку `pending` и мониторинг.

Переменные:

| Переменная | Назначение | Пример |
|---|---|---|
| `HOST` | Адрес прослушивания | `127.0.0.1` |
| `PORT` | Порт приложения | `4173` |
| `LEAD_WEBHOOK_URL` | HTTPS endpoint CRM | пусто для предпросмотра |
| `LEAD_WEBHOOK_TOKEN` | Bearer token, только на сервере | пусто |
| `PUBLIC_ORIGIN` | Публичный origin при работе через reverse proxy | `https://example.ru` |
| `LEAD_DATA_DIR` | Закрытая директория заявок | `./data` |

Один процесс сервера на одну папку заявок. Лимит запросов основан на адресе прямого соединения, не доверяет произвольному `X-Forwarded-For`. За reverse proxy требуется корректный отдельный rate limit, иначе посетители разделят общий лимит. Для production предусмотреть резервирование, политику хранения/удаления заявок, права доступа к директории и уведомления об ошибках доставки. На Windows права доступа наследуются от папки: ограничьте доступ учётной записью сервиса.

## До публикации

1. Утвердить окончательные тексты с клиникой, в том числе медицинские формулировки, лицензию, условия акции и рассрочки. Цены берутся только из заполненного брифа клиники; реквизиты и контакты сверяются отдельно.
2. Утвердить юридические документы. Диалог «Обработка данных» описывает **локальную демонстрацию**, а не готовую политику для production. Заменить его утверждёнными политикой и согласием оператора, указать сроки хранения, отзыв и обработчиков. Обновить `consentVersion` в `server.mjs`.
3. Подключить CRM и выполнить согласованную контрольную заявку с проверкой в CRM. Настроить мониторинг `pending`.
4. Согласовать публичный URL. До этого сохранён `noindex,nofollow` и не задан выдуманный canonical. После согласования настроить индексацию и canonical, сохранить существующие URL/редиректы при замене страницы.
5. Подключить существующую аналитику и цели. В исходном HTML найден счётчик Яндекс.Метрики **95513342**. В локальном предпросмотре он намеренно не запускается. Сохранить этот идентификатор при переносе, проверить счётчик и коллтрекинг в реальном окружении. Событие конверсии — подтверждённая отправка, а не клик.
6. Настроить HTTPS и `PUBLIC_ORIGIN`. Проверить мобильные устройства, звонок, рабочие часы, отзывчивость администратора и доступность карты.

GitHub Pages используется для публичного просмотра макета с записью по телефону. Действующий сайт клиники не изменялся. Для запуска рекламного трафика с онлайн-заявками остаются перечисленные выше настройки.

## Обновление

Сохраните копию текущей версии и закрытой папки заявок. Заменяйте только публичные файлы; не перезаписывайте `.env` и `data`. Выполните проверки и перезапустите один процесс приложения. Для отката верните предыдущие публичные файлы. Запуск/остановка в production определяется хостингом и отдельно не настраивались.

## Панель администратора

Панель работает локально: http://127.0.0.1:4173/admin/ . GitHub Pages публикует только сайт с записью по телефону; сервер и данные заявок туда не загружаются.

Первичная настройка (один раз):
```powershell
node scripts/init-admin.mjs
node server.mjs
```
Скрипт создаёт случайный пароль, сохраняет только salted scrypt hash в `.env`, а доступы — в `data/admin-access.txt`. Оба файла исключены из Git. Повторный запуск не меняет существующие доступы. При готовой `.env` допишите настройки в неё, не заменяйте её файлом `.env.example`.

Функции: поиск имени/телефона/номера, фильтры статуса и дат (Europe/Moscow), счётчики, карточка, рабочая заметка, история статусов. Статусы: новая, в работе, ожидаем ответ, записан, завершена, отказ. Удаление заявок и массовые операции не предусмотрены. Комментарий не предназначен для медицинских сведений.

Защита: HttpOnly SameSite=Strict cookie, CSRF token и Origin, ограничение входа (5 попыток за 15 минут), сессия 8 часов, повторная авторизация после перезапуска, проверка версии записи при конкурирующих изменениях. При HTTPS cookie получает Secure. Данные доступны только через авторизованный API и не кешируются. Локальная версия рассчитана на одного администратора и один процесс.

| Переменная | Назначение | Пример |
|---|---|---|
| `ADMIN_USERNAME` | Логин администратора | `admin` |
| `ADMIN_PASSWORD_HASH` | Соль и scrypt hash, создаются скриптом | пусто до настройки |

Проверки панели:
```powershell
node --check admin-server.mjs
node --check admin/admin.js
node --test tests/server.test.mjs tests/admin.test.mjs
```

## Публикация на GitHub Pages

```powershell
node scripts/build-pages.mjs
```
Публикуется только папка `site/`: HTML, CSS, JS, фото и шрифты из явного списка. В статической версии кнопка записи открывает телефон клиники, форма онлайн-сбора данных отключена. `noindex` сохранён для согласования макета. Локально форма и панель работают через Node.js. Сервер подключается отдельным следующим этапом; GitHub Pages не исполняет Node.js.

Кнопки записи имеют терракотовый фон с белым текстом. Световой акцент на первом экране и мобильной нижней кнопке воспроизводится два раза и отключается при prefers-reduced-motion.

## Главная и отзывы
